# 코드 구조

Vercel이 루트 `index.html`과 `api/`를 그대로 쓴다. 그래서 페이지는 루트에 둔다.

```
stockRecord/
├── index.html          화면·동작 전부
├── api/
│   ├── trades.js       매매 목록 GET/PUT
│   └── market.js       코스피·코스닥
├── data/
│   └── 매매.txt        처음 옮긴 메모 원본
├── docs/
│   ├── 진행일지.md
│   ├── 기술스택.md
│   └── 코드구조.md
├── README.md
└── .gitignore
```

## index.html

한 파일 안에 스타일, 마크업, 스크립트가 있다.

### 화면

- 헤더: 제목, 계좌 `5624-1531`
- 통계: 총 수익률, 월별평균, 거래 수, 평균, 최고, 평균 보유
- 월별 매매: 달 행을 열면 그달 종목
- 검색·필터, 추가, `매매.txt 저장`
- 전체 기록: 표(PC) / 카드(폰)
- 추가·수정 시트

### 데이터 한 건

```
id, name, buyDate, sellDate, buyPrice, sellPrice,
returnPct, holdingDays, split, note
```

`holdingDays`는 보여줄 때 `매도일 - 매수일`로 다시 계산한다. 월 묶음은 `sellDate`의 연-월이다.

### 스크립트 역할

| 함수 | 하는 일 |
|------|---------|
| `init` | 서버에서 목록을 읽고, 비었으면 시드 저장 |
| `saveTrades` | localStorage + `PUT /api/trades` |
| `pullRemote` | 4초마다 서버와 비교, 수정 창이 열려 있으면 건너뜀 |
| `holdDays` | 보유일 |
| `monthStats` | 매도월별 합계·평균·종목 |
| `renderStats` / `renderMonths` / `renderTable` | 화면 |
| `openForm` / 저장·삭제 | 추가·수정 |
| `tradesToTxt` / `exportTxt` | 같은 `매매.txt`에 전체 기록 저장 |
| `SEED` | 서버가 비어 있을 때 넣는 처음 17건 |

필터: 전체, 스윙(≤10일), 중기(11–40일), 장기(41일+), 분할매수.

## api/trades.js

Vercel Node 함수. Redis REST로 `GET`/`SET`만 한다.

- `GET` → `{ trades: [...] }`
- `PUT` `{ trades: [...] }` → 저장
- 환경 변수가 없으면 `503 KV is not connected`

키: `stockRecord:trades`.

## 데이터가 흐르는 길

```
폰 또는 PC
  → index.html
  → GET/PUT /api/trades
  → Upstash Redis

PC에서 백업할 때만
  → 매매.txt 저장
  → 로컬 같은 파일 덮어쓰기
```

GitHub의 `data/매매.txt`는 이 흐름 밖이다. 처음 메모를 남겨 둔 파일이다.
